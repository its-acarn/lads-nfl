# Form Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/form` page for LadsLadsLads 2026 with player form, points allowed by position, buy-low/sell-high signals, upcoming matchups, consistency and league team form, all over a changeable last-X-games window, in exact league scoring.

**Architecture:** Reuse the Waiver Scout's browser data layer (`fetchWaiverInputs`), widened to keep the raw stats league scoring needs. New pure logic in `helpers/form/` turns `WaiverInputs` into a `FormBoard`, tested against the committed `fixtures/waivers/2026/` snapshot. A new page renders three tables from it.

**Tech Stack:** Next 13 (static export), React 18, Chakra UI 2, TypeScript 4.8 strict, Vitest 2.

**Spec:** `docs/superpowers/specs/2026-11-20-form-page-design.md`

## Global Constraints

- League: `ladsLeagueId2026` only, held in one constant in `pages/form.tsx`.
- Points = Σ raw stat × league `scoring_settings[key]`. Never Sleeper's `pts_*`.
- Window options: 1–8 games or `'season'`; default 3. Each table has its own window; the Next 3 colouring uses the points-allowed window.
- A game counts only if the week is complete (`completedWeeks`) and the player played: `off_snp > 0` for QB/RB/WR/TE, `gp > 0` for K/DEF. Byes/absences are never zero games.
- No projections, no writes to Sleeper, no server. Static export must still build.
- `buildUsage`'s fixed `WINDOW = 3` and all Waiver Scout output stay unchanged apart from the fixture refresh.
- Tunables live in `config/form.ts` (values below).
- Team form uses every rostered player (players + reserve + taxi), injured or not; window avg, else season avg, else omitted.

## Review Focus

1. **Player traded mid-season:** each game's opponent and points-allowed attribution use the team on *that week's* stat row, not his current team. Test in Task 3.
2. **Fewer games than the window:** a player with 2 games under window 3 shows GP 2 of 3 and averages over 2, not 3. Test in Task 3.
3. **A played game with 0 points:** counts as a 0 (lowers Avg/Floor), unlike a bye. Test in Task 3.
4. **Bye in the next three weeks / end of season:** Next 3 shows `BYE` for a bye and stops cleanly when fewer than 3 weeks remain. Test in Task 4.
5. **Orphan roster (`owner_id: null`) or no team picked:** owner label `Orphan`; with no team picked, nothing is `Mine` and the Mine filter is disabled. Test in Task 5 (label) and Task 7 (UI).

```ts
export type FormPosition = Position | 'K' | 'DEF'
export const FORM_POSITIONS: FormPosition[] = ['QB', 'RB', 'WR', 'TE', 'K', 'DEF']
export type FormWindow = number | 'season'
export interface PlayerGame { week: number; team: string; opponent: string; points: number }
export type Owner = { kind: 'fa' } | { kind: 'mine'; label: string } | { kind: 'other'; label: string; ownerId: string | null }
export type Signal = 'buy' | 'sell' | null
export type MatchupTier = 'soft' | 'neutral' | 'tough'
export interface UpcomingGame { week: number; opponent: string | null; tier: MatchupTier | null } // opponent null = BYE
export interface FormUsage { snap: number; target: number; carry: number; airYards: number; rzOppsPerGame: number; passAttPerGame: number; rushAttPerGame: number }
export interface PlayerFormRow {
  playerId: string; name: string; position: FormPosition; team: string; injuryStatus: string | null; owner: Owner
  games: PlayerGame[]          // window games, oldest -> newest
  gamesPlayed: number; windowSize: number | null   // null for 'season'
  avg: number; seasonAvg: number; delta: number; floor: number; hits: number
  usage: FormUsage | null       // null for K/DEF
  usagePct: number | null; pointsPct: number | null; signal: Signal
  upcoming: UpcomingGame[]
}
export interface PointsAllowedRow { team: string; games: number; perGame: Record<FormPosition, number>; rank: Record<FormPosition, number> }
export type TeamFormGroup = 'QB' | 'RB' | 'WR' | 'TE' | 'FLEX' | 'K' | 'DEF'
export interface TeamFormRow { rosterId: number; owner: Owner; groups: Record<TeamFormGroup, number>; total: number; bench: number; rank: Record<TeamFormGroup | 'total' | 'bench', number> }
export interface FormBoard { throughWeek: number; upcomingWeek: number | null; players: PlayerFormRow[]; allowed: PointsAllowedRow[]; teams: TeamFormRow[] }
```

### Task 5: Player form rows, usage and signal

**Files:**
- Modify: `helpers/waivers/metrics.ts` — extract the inner `shares` closure of `buildUsage` into an exported `sharesOver(statsByWeek: Record<number, WeekStats>, id: string, weeks: number[]): ShareSet`; `buildUsage` calls it (behaviour unchanged, waivers snapshot must not change).
- Create: `helpers/form/owners.ts`, `helpers/form/playerForm.ts`, `helpers/form/playerForm.test.ts`

**Interfaces:**
- Consumes: Tasks 1–4, `percentiles` (`helpers/waivers/score.ts`), `ownerLabel` (`helpers/waivers/format.ts`).
- Produces:
  - `ownerMap(rosters: WaiverRoster[], users: WaiverUser[], mineOwnerId?: string): Record<string, Owner>` — over players + reserve + taxi; unknown/null owner → label `'Orphan'`. Players not in the map are free agents (`{kind:'fa'}`).
  - `buildPlayerForm(inputs: WaiverInputs, games: Record<string, PlayerGame[]>, window: FormWindow, allowed: PointsAllowedRow[], owners: Record<string, Owner>, config: FormConfig): PlayerFormRow[]` — rows for players with ≥1 window game, sorted by `avg` desc.

Field rules:
- `hits` = window games with `points >= config.hitThresholds[position]`; `floor` = min window points; `delta = avg - seasonAvg`.
- `usage` (QB–TE) over the window weeks: shares from `sharesOver`; per-game `rzOpps = rec_rz_tgt + rush_rz_att` (QB: `pass_rz_att + rush_rz_att`), `passAtt`, `rushAtt`.
- Signal pool per position: `gamesPlayed >= signal.minGames` and `usage.snap >= signal.minSnapShare[pos]`. Usage measures — QB: passAtt/g, rushAtt/g, rzOpps/g; RB: snap, carry, target, rzOpps/g; WR/TE: snap, target, airYards, rzOpps/g. `usagePct` = mean of the measures' percentiles; `pointsPct` = percentile of `avg`; gap ≥ `buyGap` → `'buy'`, ≤ `sellGap` → `'sell'`. Outside the pool, or K/DEF: all three `null`.
- `upcoming` = `upcomingGames(schedule, team, upcomingWeek(schedule), allowed, position, config)`, where `team` = `players[id].team` or the last game's team.

  - `ownerMap` labels `Mine`, other manager (`ownerLabel`), `Orphan` for `owner_id: null`; reserve players are owned.
  - `GP 2 of 3` — 2 games, window 3 → `gamesPlayed 2`, `windowSize 3`, avg over 2.
  - `floor and hits` with hand-built games and threshold.
  - `buy low` — RB in pool with top usage, bottom points → `'buy'`; reverse → `'sell'`; backup with snap 0.1 → `signal null`.
  - `K/DEF have no usage or signal`.
  - Fixture: `npm test` waivers snapshot unchanged after the `sharesOver` refactor.

Team form rules: candidates = players + reserve + taxi; value = window avg, else season avg, else omitted. Fill `rosterPositions` slots: first every QB/RB/WR/TE/K/DEF slot with the best unused player at that position, then every `FLEX` from the best unused RB/WR/TE; other slot names (BN, IR, unknown) ignored. `groups` sums per slot group, `total` = sum, `bench` = best unused RB + best unused WR + best unused TE (missing = 0). `rank` 1 = highest, per column.
